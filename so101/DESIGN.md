# SO-101 partial 데이터셋 설계

목표: 손목을 움직여 가려진 단백질과 당류 값을 모두 정확히 읽기

- **장면**: 라벨과 가림판 설정이 고정된 구성
- **관측표**: 한 장면을 각도별로 촬영하고 OCR한 기록
- **에피소드**: 시작 각도에서 출발해 실제로 방문한 관측과 행동의 순서

## 현재 설정

| 항목 | 설정 | 상태 |
|---|---|---|
| 관절 | `wrist_roll` | 확인 |
| 기계적 범위 | −157.21° ~ +162.79° | 확인 |
| 기준 자세 | 0.749999965 rad ≈ 42.97° | `v2_005`에서 확인 |
| 촬영 후보 범위 | 기준 자세 대비 −70° ~ +40° | `v2_005`에서만 확인 |
| 촬영 간격 | 5°, 총 23개 각도 | 첫 버전 설정 |
| 정책 행동 | −5°, +5°, STOP | 첫 버전 설정 |
| 이미지 | OCR 960×720, 정책 입력 224×224 | 기존 설정 재사용 |
| 최대 이동 | 8회, 시작 관측 포함 최대 9회 | 파일럿 제안 |
| 시작 각도 후보 | −30° ~ +25°, 5° 간격 | 파일럿 제안 |

`v2_005`에서는 0°에서 당류, +5°에서 단백질을 읽었다. +10°에서는 둘 다 미확정이었다. 따라서 행동 간격은 5°로 시작한다. 새 가림판에도 −70° ~ +40°가 안전한지는 장면마다 확인한다

## 가림판 생성 범위

아래 값은 `v2_005`를 기준으로 한 **파일럿 제안**이다. 실제 길이와 연동 계수를 먼저 코드에서 확인한다

| 변수 | 샘플 범위 |
|---|---|
| 초기 중심 | `v2_005` 위치 ± 두 영양 줄 사이 거리의 25% |
| 가로 폭 | `v2_005`의 0.9~1.1배 |
| 세로 두께 | `v2_005`의 0.8~1.2배 |
| 연동 방향 | +1, −1을 같은 확률로 선택 |
| 각도당 이동량 | `v2_005` 연동 계수 크기의 0.5~1.5배 |
| 이동 한계 | `v2_005` 양쪽 한계의 여유를 기준 이동폭의 ±20% 안에서 조정 |

가림판이 라벨이나 박스 테두리와 비정상적으로 겹치거나, 모든 각도에서 필요한 값을 읽을 수 없으면 해당 설정을 채택하지 않는다. 화면에서 측정한 13.5 px / 10°는 결과 확인용 수치이며 코드의 길이 단위가 아니다

## 1 장면 생성

**코드** `partial_scene.py`

1. 라벨과 가림판 설정을 시드로 생성
2. 기준 자세에서 −70° ~ +40°까지 5° 간격으로 이동·안정화·촬영·OCR
3. 장면당 원본 사진 23장과 OCR 23건을 관측표로 저장
4. 명령각, 실제 도달각, 장면 설정과 시드도 저장

`tqdm`으로 완료 장면 수, 현재 장면의 23개 각도 진행률, 경과·예상 남은 시간을 표시한다. 거절·재시도 횟수도 표시하고, 재시작할 때 완료된 장면은 건너뛴다

## 2 사전 검수와 에피소드 샘플링

**코드** `check_partial_scene.py`, `sample_partial_rollouts.py`

- 화면 이탈, 이동 실패, 형상 겹침을 검사
- 시작 화면에는 정보가 부족하고, 여러 각도를 합치면 두 값을 정확히 얻을 수 있는지 검사
- 물리적으로 글자가 드러난 경우와 OCR이 실제로 읽은 경우를 구분
- 시작 각도는 −30° ~ +25° 후보 중 안전하고 8회 이내 해결 가능한 곳에서 선택
- 최단 이동 1회 약 20%, 2~3회 약 40%, 4~6회 약 40%를 파일럿 목표로 설정
- 왼쪽과 오른쪽이 유리한 사례를 모두 확보

미래 관측표로 최단 경로를 계산할 수 있다. 이 정보는 경로 생성과 사후 검수에만 사용한다. 수집용 경로는 좌측 우선, 우측 우선, 무작위 탐색, 최단 경로를 구분해 만든다

## 3 데이터 수집

**코드** `collect_partial.py`, 기존 `ocr_memory.py`

`촬영 → OCR → 기억 갱신 → 행동 → 이동 → 다음 촬영` 순서로 기록한다

매 관측에서 이미지 경로, 관절값, OCR 원문·위치·신뢰도, 누적값과 충돌 여부를 저장한다. 매 행동에서 명령각과 실제 도달각을 저장한다. 수집용 경로는 OCR 기억상 두 값이 확보되거나 8회 이동하면 종료한다. OCR이 틀렸는지는 실제 정답과 비교해 나중에 표시한다

같은 각도에서 이동 경로와 무관하게 같은 영상이 나오는 경우에만 각도별 사진을 에피소드 간 재사용한다

## 4 전체 감사

**코드** `audit_partial.py`

- 이미지·OCR·행동·관절 상태의 연결과 장면 재현 확인
- 파일 누락, 화면 이탈, 이동 실패, 형상 겹침 확인
- 라벨 ID가 학습·검증·테스트에 중복되지 않는지 확인
- 해결 가능률, 최단 이동 횟수, 좌우 분포, OCR 오독, 잘못된 STOP 집계

기술적으로 깨진 기록만 제외한다. 오독과 탐색 실패는 보존한다. 먼저 가림판 설정을 바꾼 장면 10~20개를 확인하고 범위와 이동 횟수를 다시 결정한다

## 5 학습 입력 생성

**코드** `build_policy_dataset.py`

입력: 지금까지 본 영상과 OCR, 누적 기억, 현재 손목 각도, 행동 이력, 남은 횟수

출력: `LEFT_5`, `RIGHT_5`, `STOP`

실제 영양값, 가림판 생성값, 미래 사진과 OCR은 정책 입력에서 제외한다. 같은 라벨의 모든 변형 장면은 한 데이터 분할에만 둔다

## 6 최종 평가

**코드** `evaluate_partial.py`

미사용 라벨과 가림판 설정에서 정책이 직접 행동을 선택한다. 매 행동 뒤 MuJoCo에서 이동하고 새 영상으로 OCR을 실행한다. 고정 순회, 좌우 우선, 무작위 탐색과 같은 시작점에서 비교한다

지표: 두 값의 정확한 확보율, 잘못된 STOP 비율, 이동 횟수, 총 회전각

## 저장 구조

```text
data/partial_v1/
  dataset_config.json
  splits.json
  manifest.jsonl
  scenes/scene_000001/
    scene.json
    truth.json
    views/                   # 각도별 원본 이미지
    view_ocr.jsonl
    episodes/episode_000001.json
```

`truth.json`은 정답과 숨은 장면 설정을 담는다. 에피소드는 방문한 사진을 참조하며 파일을 복제하지 않는다
